## Deviations from the PR description (found during audit)

The PR body is largely accurate on scope and non-claims. Technical defects found
that contradict "simulation-validated release candidate" quality (detailed in
`qp-correctness-audit.md` and `red-team-review-v1.1.md`):

1. **CBF-QP is not a verified optimal solver.** `solve_cbf_qp` enumerates active
   sets only from the *violated-at-nominal* pool first and returns the first
   pool that yields any feasible candidate (`break`), so it can return a
   **feasible-but-suboptimal** point yet label it `solved`. KKT/dual conditions
   are never checked. No trusted oracle cross-validation existed.
2. **Sequential-projection fallback mislabeled.** Statuses `solved_projection` /
   `solved_projection_max_iter` are accepted as if optimal, violating the
   "never call a projection result the optimal QP result" requirement.
3. **Velocity semantics are ambiguous/mislabeled.** `max_cartesian_velocity_mps`
   pre-scales the nominal by Euclidean norm, but the QP enforces a **per-axis
   box** (`_velocity_box_constraints`), which permits up to `sqrt(3)·vmax`
   Euclidean speed on diagonal corrections. `test_velocity_limit_enforced`
   only passes because it moves along a single axis.
4. **No independent discrete-step safety validator.** The filter checks only the
   linear CBF residual on `u*`, not whether the actual next state `p_next`
   satisfies workspace+margin / obstacle+margin.
5. **Weak obstacle test.** `test_obstacle_barrier_intervention` passes on
   `dist >= r-1e-3 OR res.intervened` — i.e., merely because intervention
   occurred, not because the accepted state is provably outside the sphere.
6. **Undocumented heuristic.** `sew_orientation.py` applies `chain[2] * 0.5`
   with no named parameter or rationale.
7. **Benchmark design.** `results/v1.1/benchmark-summary.json` has
   `repeatability: {}` (empty), a single replicate (`n_rows=60` = 6 combos × 10
   trajectories × 1), and no std/p95/p99/CIs; inputs are not provably paired
   across methods.

These are addressed (or, where blocked by the missing ROS/Docker runtime in this
VM, explicitly deferred) in later phases. No README claim was edited before this
audit.
